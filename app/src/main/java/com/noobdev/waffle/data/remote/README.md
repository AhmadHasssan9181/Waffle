# data/remote

One file per external service. All calls are `suspend` and return nullable/`Result` values — no
screen should see an exception.

| File | Service | Key? |
| --- | --- | --- |
| `OpenCage.kt` | Reverse geocoding and online forward-search fallback | `OPENCAGE_API_KEY` in `local.properties` |
| `OfflineGeocoder.kt` | Bundled POI + named-road search, tokenised and ranked, no network | none |
| `OpenMeteo.kt` | Hourly weather | none |
| `OpenRouteService.kt` | Online routing, `avoid_features`, alternatives and `avoid_polygons` | `ORS_API_KEY` |
| `TomTomTrafficRepository.kt` | Live traffic flow for the navigation ETA | `TOMTOM_API_KEY` (optional) |
| `GeminiClient.kt`, `GeminiInstance.kt` | AI situation brief | `GEMINI_API_KEY` |
| `MapStyles.kt` (in `feature/map`) | MapTiler style URLs | `MAPTILER_API_KEY` |

Keys are injected through `build.gradle.kts` into `BuildConfig`. Rotate any key that has ever been
committed. API clients here must set a descriptive `User-Agent`; Overpass and Wikimedia require it.

**Offline search:** `offline_places.tsv` (fast line parser) and `offline_roads.json` (named OSM
highways) are loaded by `OfflineGeocoder`. The query is tokenised and scored against name, address,
road refs and alternate names. If nothing matches offline and the phone is online, `MapSearch`
falls back to `searchLocations` from OpenCage. Road data is generated by `tools/roads`; the places
TSV is generated by `tools/places`.
